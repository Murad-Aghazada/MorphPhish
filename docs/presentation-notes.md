# Presentation notes

**Why FastAPI?** Typed schemas, OpenAPI generation, concise service APIs, and good Python ecosystem integration.

**Why PostgreSQL?** Relational integrity is useful for personas, campaigns, targets, events and auditable lifecycle state while JSON fields handle explainable factors/metadata.

**Why GoPhish?** It is isolated behind a provider because campaign delivery is not the research novelty; the platform adds contextual risk/scenario/analytics orchestration around an established engine.

**Why adapters?** Mock HR/context can be replaced by controlled read-only enterprise integrations without rewriting domain logic.

**Why LLM abstraction?** Provider choice and outages do not leak into business rules; mock mode supports deterministic demos.

**Why approval?** LLM output is untrusted. A human gate separates generation from execution and creates an auditable control.

**How risk scoring works?** Deterministic weighted factors are visible in the UI/API and can be recalculated. No opaque ML model is required for the prototype.

**Why passwords are never stored?** The learning signal is whether a simulated risky action occurred, not the credential value. Data minimization removes an unnecessary high-impact secret.

**Why mock context?** It proves contextual generation while avoiding collection of real internal communications or HR data.

**Future HR/SIEM/SOC integration:** add scoped adapters/webhooks, pseudonymous identifiers, read-only access, correlation IDs and audit controls.

**Multi-tenancy:** tenant IDs on domain tables, authorization boundaries, per-tenant encryption/secrets, tenant-scoped jobs and database isolation/RLS.
